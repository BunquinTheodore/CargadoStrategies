# Cargado Strategies v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan runs as an ultracode Workflow in waves; tasks in one wave own disjoint files.

**Goal:** Ship the owner-approved v2: seven new own services, insurance redirect, navy backgrounds, the services orbit (Home + Services), the logo in the header, founder photos, a Contact page with Google Calendar booking, Firebase accounts with client/partner/admin dashboards and points, legal drafts, and third-person copy.

**Architecture:** The scroll-film site in `site/` stays as is; new film scenes and one new film page (`contact.html`) follow the section contract in `CLAUDE.md`. Accounts and dashboards are separate "app" pages that are not scroll films and are the only pages that load Firebase (from the official CDN, lazily). Server work lives in Vercel functions under `api/` using Node built-ins and REST (no new dependencies); pure logic (slots, points) is shared modules with `node:test` tests.

**Tech Stack:** Plain HTML/CSS/ES modules, esbuild (`build.mjs`), Vercel functions (Node 24), Google Calendar REST v3 (OAuth refresh token), Firebase Auth + Firestore (JS SDK 10.12.2 from `https://www.gstatic.com/firebasejs/10.12.2/`, Firestore REST + service-account JWT on the server), Resend REST, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-25-cargado-v2-design.md` (read it with this plan; § numbers below refer to it).

## Global Constraints

- Read `CLAUDE.md` first; its fixed rules hold except as changed in spec §5 "Rule changes".
- Colour: black and gold, plus navy only in background tokens (`--navy-*`) of the `ink` field and app-page backgrounds. Never on buttons, text, links, icons, borders.
- Display type Times New Roman stack, Title Case written in markup; Manrope body; Poppins labels; 14 px floor; 44 px tap targets; works from 360 px.
- Film scenes: ≤ 60 words, ≤ 12 elements, ≤ 3 groups, fit one screen at all 9 viewports in film, `--flow`, `--touch`; gold field at most once per page.
- Animate only transform, opacity, clip-path. No `console.log`. No new npm dependencies. Small functions, named constants, match surrounding comment density.
- Owner content only in `site/assets/js/config.js`. Never invent facts; unknowns are `<span class="ph">[bracket]</span>`.
- No prices for the new services. Copy names "Cargado Strategies" in the third person (spec §6.6).
- Secrets only in Vercel env vars / `.env.local`; the repo is public.
- Booking: time zone `America/Winnipeg`; slots 10 min; first 15:30, last start 20:50; every day; lead time 2 h; horizon 60 days; one active future booking per email.
- Points: 5 per qualifying event (§8.4), awarded once per event id; no spending yet.
- Insurance link: `INSURANCE_INQUIRY_URL = 'https://policyreview.leeholgado.com/'`.
- Pages must work with Google **unconfigured** (booking falls back to email) and with the Firebase web config present but the project not fully set up (Auth providers or Firestore not enabled yet, no server service account): sign-in failures show a friendly message, admin APIs answer 503 `not_configured`, and no page logs console errors or warnings on load. The "Accounts are coming soon" state still exists for an empty `FIREBASE` (tests cover both by stubbing config).
- Never load Firebase Analytics.
- Agents: never use port 8000, never run git, at most ONE headless-browser tool at a time, stop servers/Chromes you start (CLAUDE.md). Commits happen once at the end, only if the owner asks.
- Tests: `node --test tests/` (add `"test": "node --test tests/"` to package.json in Task 1).

## Review Focus

1. **Daylight-saving days in Winnipeg** (2026-11-01, 2027-03-14): slots must still run 15:30-20:50 local, 34 slots, no duplicate or missing hour. Test in Task 4.
2. **Visitor outside Central time / near midnight:** the date list starts at today *in Winnipeg*, labels say "Central Time", and the chosen slot is sent as an ISO instant. Test in Task 4 (date boundary) and Task 9 (UI label).
3. **Two visitors take the same slot:** the second `POST /api/book` gets 409 `slot_taken` and the UI reloads slots with a message. Test in Task 5.
4. **Google errors or not configured:** `/api/book` never loses the request: it emails the owner and the visitor gets "time to be confirmed by email" (200 `{ ok: true, pending: true }`). Test in Task 5.
5. **Cron or retry runs twice:** completing bookings and awarding points is idempotent (point doc id = event id). Test in Task 11.
